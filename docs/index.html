Plugin decisoes

Planeje ideias e registre decisões com o Claude Code

O plugin decisoes faz o Claude discutir as decisões com você de forma crítica, uma de cada vez, e registrar o porquê de cada escolha num documento que continua fazendo sentido para quem não estava na conversa.

São dois comandos, usados de jeitos diferentes:

Você digita /decisoes:tira-do-papel

Quando tem uma ideia e ainda não tem projeto. O Claude cria o projeto e conduz as decisões até ele estar pronto para construir.

O Claude sugere /decisoes:discute

Quando, no meio do trabalho, a conversa vira uma escolha entre alternativas. Ele propõe abrir a discussão e espera o seu OK.

Instalar

É para o Claude Code: no terminal ou na aba Code do Claude Desktop.

  1. Abra o Claude Code

    No Claude Desktop, uma sessão na aba Code; ou o comando claude no terminal. Qualquer pasta serve.

  2. Peça para ele instalar

    Copie a frase e mande para o Claude:

    Siga o INSTALAR-COM-CLAUDE.md de https://github.com/gersonkm/claude-skills

  3. Responda quando ele pedir OK

    O Claude confere o que falta e instala o plugin. Se faltar algum programa, ele explica para que serve e pede a sua permissão antes de instalar. No fim, ele liga a atualização automática e testa se ficou funcionando.

    No Windows, ele pode pedir para instalar o Git for Windows, de que os scripts do plugin precisam. Se você só usa o Desktop, ele pode propor instalar também o Claude Code de terminal, que a instalação usa. Fica com a mesma conta e os mesmos plugins.

  4. Abra uma conversa nova

    O plugin só começa a valer numa sessão aberta depois da instalação. Dali em diante, as melhorias chegam sozinhas.

Prefere instalar à mão?

No Claude Code, digite:

/plugin marketplace add gersonkm/claude-skills
/plugin install decisoes@gersonkm

Para receber as atualizações sozinho: /plugin → aba Marketplaces → gersonkm → Enable auto-update. No Windows, instale antes o Git for Windows (winget install --id Git.Git -e).

Como usar

Há duas formas de usar o plugin. Os exemplos abaixo são baseados em sessões reais de teste, encurtadas. As notas ao lado mostram o que o plugin está fazendo em cada momento.

Começar um projeto do zero

Você digita /decisoes:tira-do-papel seguido da ideia. Não precisa criar pasta antes: abra o Claude Code na pasta onde guarda seus projetos, ou em qualquer outra. Ele sugere onde criar a pasta nova, nunca dentro de outro projeto, e pergunta quando não souber.

No exemplo, alguém quer um caderno de receitas digital para a família.

✻ Claude Code~/projetos (já tem outros dois projetos)
>

/decisoes:tira-do-papel quero fazer um app simples pra minha família guardar e compartilhar as receitas da casa, tipo um caderno de receitas digital

Você chama. Este comando o Claude nunca aciona sozinho, porque ele cria pasta e repositório.
⏺

Antes de criar qualquer coisa, quero entender melhor. Pode responder só com o número e a letra.

1. Quem vai usar? A) só a casa · B) a família estendida · C) começa em casa e depois abre

2. O que te fez pensar nisso agora? A) receitas espalhadas · B) tem receita que só uma pessoa sabe fazer · C) quer aprender a fazer um app

(e uma terceira pergunta, sobre como a família usaria no dia a dia)

Entender antes de criar. Nada é criado até a ideia estar clara: o nome da pasta nasce desse entendimento.
>

1B, 2B (a receita da minha avó só ela sabe fazer) e um pouco de C, 3A

Responder pelo número é o bastante.
⏺

Uma coisa que preciso dizer agora, porque é mais importante que o app: a receita da sua avó não pode esperar o app ficar pronto. Receita de avó é "farinha até dar o ponto". Isso se registra melhor filmando ela fazendo.

O nome da pasta (vale também para o GitHub):

  • A) receitas-da-familia
  • B) caderno-de-receitas
  • C) receitas-da-vo
Recomendo A: é claro e não fica pequeno quando o resto da família começar a colocar receitas.
Crítica sincera, não só execução: aponta o que importa mais que o pedido. Depois, uma rodada com opções e uma recomendação.
>

A. Pode criar.

OK seu antes de criar a pasta.
projetos/receitas-da-familia/ docs/decisoes/ativo/receitas-da-familia.md
⏺

Pasta criada, com o primeiro registro. Com o seu OK, crio o repositório privado no GitHub: só você enxerga, porque o documento guarda o plano da ideia. Posso criar?

Sempre privado. Público só se você pedir com todas as letras.
>

Pode.

Outro OK seu, porque o repositório fica fora da sua máquina.
github.com/… (privado)
⏺

Rodada 1: app próprio ou algo pronto? A) uma pasta compartilhada · B) construir o app · C) os dois, em etapas

Recomendo C: guardar as receitas da avó não pode ficar refém do sucesso do app.

(as rodadas seguem: primeira versão, formato, como testar com a família, custo)

Uma decisão por vez, cada uma registrada no documento com o porquê. A cada bloco de decisões, salva no GitHub.
⏺

A ideia está pronta para começar a construir. Salvei as decisões e o CLAUDE.md. Abra uma sessão nova dentro da pasta receitas-da-familia: é lá que a construção começa.

Entrega o CLAUDE.md, o resumo que o Claude lê em toda sessão daquele projeto.
receitas-da-familia/CLAUDE.md

Discutir decisões com prós e contras

Quando, num projeto, aparece uma escolha entre caminhos, o Claude sugere /decisoes:discute. Você não precisa digitar nada: só conta o que quer.

✻ Claude Code~/projetos/receitas-da-familia
>

Quero que a família seja avisada quando eu colocar uma receita nova no site. Pode ser por e-mail, por WhatsApp ou só uma página de novidades, não sei qual é melhor.

Uma conversa comum, sem comando.
⏺

Essa escolha tem prós e contras de verdade, então vale discutir antes de implementar. Sugiro abrir uma discussão com /decisoes:discute. Assim a escolha fica registrada com as alternativas descartadas e o motivo. Só abro o documento se você quiser.

(e já adianta uma primeira impressão das três opções)

O Claude percebeu sozinho que era uma escolha entre alternativas, e sugeriu. Não criou nada.
>

Sim, pode abrir.

A decisão de abrir é sua.
docs/decisoes/ativo/aviso-de-receita-nova.md
⏺

Pontos que precisamos decidir, em ordem: escopo, canal, disparo e conteúdo. Antes, preciso saber como a família funciona hoje, porque a resposta muda a escolha do canal:

Grupo da família: A) existe e todo mundo lê · B) existe mas está abandonado · C) não existe

Quem vai ler: X) todos usam bem o celular · Y) tem gente que precisa receber sem fazer nada

Uma resposta como "A, Y" já basta.

Pergunta antes de chutar. Ele admite que a primeira impressão supôs coisas não confirmadas, e não inventa motivo: o que falta fica marcado como pendente no documento.

O que fica registrado

Cada discussão vira um arquivo no próprio projeto. Exemplo ilustrativo de como fica o documento do segundo cenário, depois de algumas rodadas:

receitas-da-familia/docs/decisoes/ativo/aviso-de-receita-nova.md
Aviso de receita nova
em-implementacao
Problema

A família quer saber quando entra uma receita nova no site. Tem gente com pouca intimidade com tecnologia, que precisa receber o aviso sem fazer nada.

Decisões
D1. Página de novidades, com o link no grupo da família

Por quê: o grupo de WhatsApp já existe e todo mundo lê; quem tem pouca intimidade com tecnologia recebe o aviso sem fazer nada.

Descartado: e-mail, porque exigiria manter uma lista de endereços; WhatsApp automático, porque a API é paga.

D2. O aviso sai à mão, não sozinho

Por quê: entram poucas receitas por mês, e automatizar não compensa por enquanto.

  1. ativo/ · em-discussao
  2. →
  3. em-implementacao
  4. →
  5. implementado
  6. →
  7. arquivo/publicado/ · congelado

Enquanto a obra está aberta, o documento cresce com decisões novas (D3, D4…). Depois de entregue, ele vai para o arquivo e não muda mais: se a decisão for revista um dia, nasce um documento novo que aponta para este.

O que acontece sem você ver

  • As regras chegam em toda sessãoÉ isso que permite ao Claude sugerir a discussão na hora certa.
  • O arquivo é protegidoAntes de ler ou editar um documento arquivado, o Claude pede a sua confirmação, para não tratar decisão antiga como se fosse o estado de hoje.
  • Conversa longa não perde o métodoSe houver uma discussão em andamento quando a conversa for resumida para caber na memória do Claude, ele relê o método da discussão.
  • Atualiza sozinhoCada melhoria publicada chega na sessão seguinte, se a atualização automática estiver ligada.
